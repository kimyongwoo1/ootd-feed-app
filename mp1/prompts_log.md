- 사용한 AI 도구: Claude (Cowork)
- 기록 방식: **실제 입력**은 내가 AI에게 보낸 문장을 그대로 옮겼다. 짧게 물어본 경우가 많아서, 그때 함께 보낸 자료와 원했던 내용을 **요청 의도**에 덧붙였다. **다시 쓴다면**은 결과를 보고 나서 이렇게 물었으면 더 빨랐겠다고 생각한 프롬프트다.

## 1. 개발 환경 설치

- 실제 입력: "flutter 설치하는거 자세하게 알려줘"
- 요청 의도: Windows 노트북에 Flutter를 처음 설치하는 상황. 무엇을 어떤 순서로 설치하는지, 설치가 끝났는지 어떻게 확인하는지 알고 싶었다.
- AI 응답: Git → VS Code → VS Code의 Flutter 확장 설치 → 확장의 'Download SDK'로 SDK 설치 → PATH 추가 → `flutter doctor`로 확인하는 순서를 단계별로 안내. 설치 경로에 한글·공백이 없어야 한다는 주의점도 알려 줌
- 판단: 채택. 공식 문서의 빠른 설치 방법과 같은 순서라 그대로 따라 했다. 설치 경로는 `C:\dev\flutter`처럼 영어로만 정했다.
- 검증: `flutter doctor`에서 Flutter·Chrome 항목에 체크 표시가 나오는 것을 확인했다.
- 다시 쓴다면: "Windows 11 노트북에 Flutter를 처음 설치하려고 해. Chrome으로 실행하는 것까지만 필요하고 Android Studio는 아직 안 깔 거야. 설치 순서와 `flutter doctor`에서 무엇이 나오면 성공인지 알려줘."

## 2. 설치 후 첫 실행

- 실제 입력: "실행해볼려면 어떻게 하면돼" → (카운터 앱 화면 캡처) "이렇게 나오는게 정상인거야"
- 요청 의도: 프로젝트를 만들고 실행하는 명령어를 알고 싶었다. 실행했더니 숫자 버튼 화면이 나와서, 이게 맞는 결과인지 확인하고 싶었다.
- AI 응답: `flutter create` → `flutter run -d chrome` 순서를 안내. 캡처 화면은 Flutter 기본 예제(카운터 앱)라서 설치와 실행이 정상이라고 설명
- 판단: 채택. 기본 예제가 뜨는 것으로 개발 환경이 준비된 것을 확인하고 다음 단계로 넘어갔다.
- 다시 쓴다면: "flutter create로 만든 기본 앱을 Chrome에서 실행하는 명령어 알려주고, 정상이면 어떤 화면이 나오는지도 알려줘."

## 3. 첫 피드 앱 시도

- 실제 입력: "요구사항 명세서의 기능적 요구사항 중에서 주요 요구사항 2개정도만 flutter로 구현해보고싶은데 해줄래" (팀 요구사항 명세서 PDF 첨부)
- 요청 의도: 팀 프로젝트(OOTD 피드 앱) 명세서에서 핵심 기능 두 개만 먼저 만들어 보면서 Flutter 구조를 익히고 싶었다.
- AI 응답: 피드 목록(B1)과 게시글 작성(B2)을 골라 구현. 처음엔 Firebase 연동을 제안했다가, 서버 없이 메모리에 저장하고 image_picker로 사진을 고르는 버전으로 정리
- 판단: 부분 채택. 피드 → 글쓰기 흐름과 화면 나누는 방식은 참고했다. 하지만 MP1은 서버 없이 더미 데이터로 만드는 단계라 Firebase와 사진 업로드는 뺐다.
- 다시 쓴다면: "첨부한 명세서의 B1(피드 목록)과 B2(글쓰기)만 Flutter로 만들어 줘. 서버는 아직 쓰지 말고 더미 데이터로, 화면은 피드·글쓰기 두 개만."

- AI 응답: 화면 3개(피드·글쓰기·상세), 더미 게시글 10개, 기능 4개를 가이드 순서대로 구현. README(화면 구성·더미 데이터 구조·실행 절차)와 테스트 코드까지 구성

- 다시 쓴다면: "첨부한 MP1 가이드의 '화면 3개 · 기능 4개 · 통과 기준 4개'에 딱 맞춰서 만들어 줘. 서버·외부 패키지 없이, 제출 폴더 구조와 README 필수 항목도 가이드대로."

## 5. 기능 1 — 더미 게시글 10개 카드 표시

- 실제 입력: (4번 요청에 포함) 가이드의 기능 1 "더미 게시글 10개 카드 표시"
- AI 응답: 가짜 닉네임(초록고래, 새벽코더 …)과 더미 문장 10개를 만들고, 작성 시각은 고정 날짜가 아니라 '지금 − N분'으로 계산. 3분 전 ~ 4일 전으로 고르게 나눔. 프로필 사진 대신 닉네임 첫 글자 아이콘 사용
- 판단: 채택. 실명·연락처·실제 사진이 없어서 통과 기준 4번(개인정보 없음)을 만족한다. 언제 실행해도 분·시간·일 표시를 한 화면에서 모두 확인할 수 있어서 좋았다.
- 검증: 피드에 카드 10개가 스크롤되고, '3분 전' ~ '4일 전'이 섞여 나오는 것을 확인했다. (screenshots/01_feed.png)

## 6. 기능 2 — 글쓰기 → 피드 최상단에 추가

- 실제 입력: (4번 요청에 포함) 가이드의 기능 2 "글쓰기 → 피드 최상단에 추가"
- AI 응답: Provider 같은 상태관리 패키지 없이, `Navigator.push`로 글쓰기 화면을 열고 `Navigator.pop`으로 돌려받은 Post를 `_posts.insert(0, post)`로 맨 앞에 넣는 방식. 내용이 비어 있으면 [게시] 버튼 비활성화, 닉네임을 비우면 '익명'
- 판단: 채택. 데이터를 주고받는 화면이 두 개뿐이라 상태관리 패키지보다 이 방식이 단순하고 이해하기 쉬웠다.
- 검증: 글을 쓰고 [게시]하면 '방금 전'으로 맨 위에 생기고, 내용이 비면 [게시]가 회색인 것을 확인했다. (screenshots/02_compose.png)

## 7. 기능 3 — 게시글 탭 → 상세 화면

- 실제 입력: (4번 요청에 포함) 가이드의 기능 3 "게시글 탭 → 상세 화면"
- AI 응답: 카드의 `InkWell.onTap`에서 `Navigator.push(DetailScreen(post: p))`로 이동. 상세 화면에서는 내용을 자르지 않고 전부 보여 줌
- 판단: 채택. 피드에서는 내용이 3줄까지만 보이고, 상세에서 전체를 보도록 역할을 나눴다. 상대 시간 옆에 정확한 작성 시각(2026.11.04 15:26)도 같이 보이게 했다.
- 검증: 카드를 누르면 상세 화면으로 가고, 뒤로가기로 피드에 돌아오는 것을 확인했다. (screenshots/03_detail.png)

## 8. 기능 4 — 상대 시간 표시

- 실제 입력: (4번 요청에 포함) 가이드의 기능 4 "작성 시각을 '5분 전'처럼 표시"
- AI 응답: 패키지 없이 `DateTime.now().difference()`로 방금 전 / N분 전 / N시간 전 / N일 전을 만들고, 7일 이상은 날짜로 표시. 피드는 1분마다 다시 그려서 켜 둔 동안에도 시간이 바뀜
- 판단: 채택. intl 같은 패키지를 추가하지 않아도 충분했다. 테스트에서 '지금'을 고정할 수 있게 `now`를 인자로 받도록 만든 점이 좋았다.
- 검증: `flutter test`에서 상대 시간 테스트 5개(방금 전·분·시간·일·날짜)가 통과했다. 피드를 켜 두고 1분 뒤 '방금 전'이 '1분 전'으로 바뀌는 것도 확인했다.
