# 커뮤니티 가이드라인 — 미니 피드

미니 피드는 **익명**으로 오늘의 코디와 일상을 나누는 공간입니다.
이름을 밝히지 않는 만큼, 서로를 배려하는 약속을 지켜 주세요.
이 문서는 앱의 신고 사유와 서버 규칙(`app/supabase/mini_posts.sql`)에 그대로 반영되어 있습니다.

---

## 1. 금지 콘텐츠

아래 내용은 게시글과 댓글 모두에서 금지됩니다. 앱의 신고 사유 5가지는 이 목록과 1:1로 대응합니다.

| 신고 사유 (서버 값) | 금지 내용 | 예시 |
|---|---|---|
| 스팸·광고 (`spam`) | 홍보·판매 글, 같은 내용 반복, 외부 사이트·오픈채팅 유도 | "○○ 쇼핑몰 할인코드", 같은 글 10번 올리기 |
| 욕설·혐오·괴롭힘 (`abuse`) | 욕설, 특정인·성별·지역·외모 등을 비하하거나 공격하는 표현, 따돌림 | 다른 사용자의 코디를 조롱하는 글, 특정인 저격 |
| 음란·선정적인 내용 (`sexual`) | 성적인 표현, 성적 대상화 | 신체 부위를 성적으로 묘사하는 글 |
| 개인정보 노출 (`privacy`) | 본인·타인의 실명, 전화번호, 이메일, 주소, 학교·학번, 얼굴 사진, SNS 계정 | "○○고 3학년 김○○ 코디", 연락처 남기기 |
| 기타 (`other`) | 위에 없지만 불법이거나 다른 사람에게 피해를 주는 내용 | 불법 거래, 저작권 침해, 거짓 정보 유포 |

> 익명 서비스이므로 **본인 개인정보도 올리지 않는 것**이 원칙입니다. 앱의 글쓰기·댓글 입력창에도 이 안내를 표시합니다.

## 2. 신고 처리 원칙

### 신고 방법
게시글 상세 화면 오른쪽 위 🚩 → 사유 1개 선택(필수) → 자세한 설명(선택, 200자) → [신고하기]

### 처리 단계

| 단계 | 언제 | 무엇이 일어나나 | 서버에서 |
|---|---|---|---|
| ① 접수 | 신고 즉시 | 신고 사유·설명·시각이 서버에 기록됩니다. | `mini_reports` 에 `status = 'pending'` 으로 저장 |
| ② 신고자 보호 | 신고 즉시 | 신고한 글은 **신고자 본인의 피드에서 바로 숨겨집니다.** 다시 보지 않아도 됩니다. | RLS: 내가 신고한 글은 나에게 안 보임 |
| ③ 자동 숨김 | 서로 다른 사용자 **3명 이상** 신고 | 운영자가 확인하기 전이라도 **모든 사용자에게 임시로 숨겨집니다.** 작성자 본인에게만 보입니다. | `report_count ≥ 3` 이면 RLS가 숨김 |
| ④ 운영자 검토 | 접수 후 24시간 이내 (목표) | 운영자가 Supabase 대시보드에서 신고 내용과 글을 확인합니다. | `mini_reports` 조회 |
| ⑤ 결정 | 검토 후 | **위반:** 글 삭제(댓글·좋아요·신고 기록도 함께 삭제). **위반 아님:** 숨김 해제, 신고는 `dismissed` 로 기록. | `delete` 또는 `status = 'dismissed'` + `report_count = 0` |

### 원칙
- **한 사람은 같은 글을 한 번만 신고할 수 있습니다.** 한 사람이 여러 번 눌러 글을 숨기는 것을 막기 위해서입니다. (`unique(post_id, reporter_id)`)
- **신고 사유는 정해진 5가지 중에서만** 고를 수 있습니다. 서버가 다른 값을 거부하므로 운영자가 빠르게 분류할 수 있습니다.
- **신고자는 공개되지 않습니다.** 작성자를 포함해 누구도 누가 신고했는지 볼 수 없습니다.
- **3건이라는 기준**은 소규모 서비스에서 한두 명의 악의적 신고로 글이 사라지지 않도록 하면서, 명백한 위반 글은 운영자 확인 전에 빠르게 가리기 위한 값입니다.
- **허위·보복 신고**가 반복되면 해당 신고는 `dismissed` 로 처리하고, 이후 서비스 이용이 제한될 수 있습니다.
- **내 글은 신고할 수 없습니다.** 내 글의 신고 버튼은 표시하지 않습니다.

## 3. 상호작용 데이터 노출 범위와 이유

| 데이터 | 누구에게 보이나 | 보이지 않는 것 | 이유 |
|---|---|---|---|
| 좋아요 **수** | 모든 사용자 | — | 글의 반응을 알 수 있는 최소한의 정보 |
| **누가** 좋아요했는지 | **아무에게도 공개하지 않음** (작성자 포함) | 좋아요 누른 사람 목록 | 아래 참고 |
| 내가 좋아요했는지 | 나만 | 다른 사람의 좋아요 여부 | 하트 색 표시에만 필요 |
| 댓글 (닉네임·내용·시각) | 모든 사용자 | 화면에 익명 ID는 표시하지 않음 | 대화하려면 내용이 보여야 함. ID 대신 직접 입력한 닉네임만 표시. 익명 ID는 '내 댓글' 표시용으로만 사용 (무작위 값이라 사람을 특정할 수 없음) |
| 댓글 수 | 모든 사용자 | — | 상세에 들어가기 전 참고용 |
| 신고 | 신고한 본인만 (자기 신고 기록) | 신고자, 신고 사유, 신고 수 | 보복 방지 |
| 전체 신고 목록 | 운영자만 (Supabase 대시보드) | — | 신고 처리 |

### "누가 좋아요했는지"를 숨긴 이유
1. **익명성 보호:** 좋아요 목록이 보이면 같은 사람이 어떤 글들에 반응했는지 모아 볼 수 있어, 익명이어도 활동이 추적됩니다.
2. **관계 추측과 압박 방지:** "누가 눌렀나, 누가 안 눌렀나"를 확인하는 문화가 생기면 눌러야 한다는 압박과 저격·따돌림으로 이어질 수 있습니다.
3. **목적에 충분:** 작성자에게 필요한 것은 "몇 명이 좋아했는지"이고, 숫자만으로 그 목적이 충족됩니다.

### 서버에서 어떻게 지키나
화면에서만 숨기는 것이 아니라 **서버 규칙(RLS)으로 막았습니다.** 앱을 고쳐서 직접 요청하더라도 다른 사람의 좋아요·신고 기록은 받을 수 없습니다.

```sql
-- 좋아요: 내 것만 읽을 수 있음 → 다른 사람의 좋아요 기록은 서버가 주지 않는다
create policy "likes 내 것만 읽기" on mini_post_likes
  for select to authenticated using (user_id = auth.uid());

-- 신고: 내 신고만 읽을 수 있음
create policy "reports 내 것만 읽기" on mini_reports
  for select to authenticated using (reporter_id = auth.uid());
```

좋아요·댓글·신고 **수**는 서버 트리거가 계산합니다. 앱에는 게시글 수정 권한이 없어서 숫자를 조작할 수 없습니다.

## 4. 개인정보 원칙 (MP2부터 유지)
- 로그인은 **익명 인증만** 사용합니다. 이메일·전화번호·실명을 받는 코드와 DB 칸이 없습니다.
- 사용자는 기기마다 발급되는 익명 ID(uuid)로만 구분합니다.
- 설정 키는 `.env` 로 분리하며 제출물과 저장소에 넣지 않습니다.
